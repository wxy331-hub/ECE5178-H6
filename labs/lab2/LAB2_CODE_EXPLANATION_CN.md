# Lab 2 代码实现说明

## 1. 任务目标

Lab 2 使用扩展卡尔曼滤波器（Extended Kalman Filter，EKF）估计 Sphero 的位置，并让机器人完成一条可重复的 200 步轨迹。仿真器提供用于比较的真实状态（ground truth）；连接实机时，机器人提供航向角和速度测量。

完整程序的执行流程为：

```text
重置仿真器和机器人
  -> 对齐两者的初始航向
  -> 运行四段、每段 50 步的正方形轨迹
  -> 使用标定后的运动模型预测状态
  -> 使用航向和速度测量修正状态
  -> 记录后验位置与协方差
  -> 第 200 步后停止机器人并断开蓝牙
  -> 写入并验证自动评分 CSV
  -> 在终端显示两项评分指标
  -> 自动生成分析图
```

主要文件包括：

- [`EKF.py`](./EKF.py)：运动模型和 EKF 实现；
- [`lab2.py`](./lab2.py)：实验流程、机器人连接、轨迹与输出；
- [`analyze_lab2.py`](./analyze_lab2.py)：CSV 验证、指标计算和分析图；
- [`test_lab2.py`](./test_lab2.py)：离线回归测试。

## 2. 状态、控制量与测量量

EKF 状态定义为：

```text
x = [位置 x, 位置 y, 航向角, 速度]
```

控制输入为：

```text
u = [速度指令, 航向指令]
```

滤波器实际使用的测量量为：

```text
z = [测得航向角, 测得速度]
```

环境原始观测可能还包含位置和碰撞信息，但 EKF 只选择航向与速度。这样可以避免把带噪声的里程计位置错误地当成第二个相互独立的位置传感器。

坐标约定为：

- 航向 `0 rad` 指向 `+y`；
- 航向 `pi/2 rad` 指向 `+x`；
- 所有角度都归一化到 `[-pi, pi)`。

## 3. 实验主要参数

[`lab2.py`](./lab2.py) 中的主要常量为：

```python
DT = 0.1
N_STEPS = 200
COMMAND_SPEED_LIMIT = 0.15
SIM_SPEED_LIMIT = MODEL_CONFIG["max_speed_m_s"]   # 0.50
RAW_SPEED_LIMIT = 15
```

因此一次实验大约运行 20 秒。默认轨迹使用 `0.10 m/s` 的速度指令，真实机器人还受到更底层的 `15/255` 原始速度上限保护。

这里的两个速度上限是**不同的物理量**，早期版本用同一个 `VELOCITY_LIMIT = 0.15` 表示两者，导致了系统性误差：

- `COMMAND_SPEED_LIMIT` 是**指令上限**。`Robot` 用它把速度指令换算成原始字节（`speed_raw = speed_cmd / vel_limit * raw_speed_limit`），改动它会直接改变真实机器人的行进速度，因此必须保持 `0.15`。
- `SIM_SPEED_LIMIT` 是**观测量程**，即传感器能测到的速度范围。在 `0.10` 的速度指令下，模型稳态速度为 `2.69 x (0.10 - 0.0322) = 0.182 m/s`，比 `0.15` 高出 21%，所以旧代码里每一步的仿真速度观测都被 `np.clip` 压在量程上限上。量程必须覆盖模型可能产生的全部输出，因此取模型自身的硬上限 `0.50`。

修正这一点后，仿真的平均马氏距离从 `2.29` 降到 `0.053`，位置 RMSE 从 `2.8 cm` 降到 `3.8 mm`。

## 4. 标定后的运动模型

过程模型保留了 Lab 1 的非线性运动方程，包括：

- 速度指令死区；
- 电机一阶响应；
- 加速和减速限制；
- 最大转向角速度；
- 中点位置积分。

Lab 2 使用与 Lab 1 完全相同的速度增益：

```python
"speed_gain": 2.69
```

早期版本曾把 Lab 2 的增益降到 `2.47`，理由是仿真正方形系统性地大于 EKF 轨迹。**这个结论现在已被证明是错的**：轨迹偏小的真正原因是硬件速度"测量"取自 `api.get_speed()`，而该接口返回的是指令目标值而非传感器读数（其文档写明 "current target speed"），再叠加上文所述的观测量程截断。降低增益只是在补偿这两个缺陷，代价是运动模型不再描述真实机器人。

对 2026-08-14 真机日志的 locator 轨迹做差分，可以直接反推出真实增益：

| 估计方法 | 第 1 条腿 | 第 2 条腿 | 第 3 条腿 | 第 4 条腿 | 均值 |
| --- | --- | --- | --- | --- | --- |
| 逐步速度中位数 | 2.93 | 2.60 | 2.52 | 2.42 | 2.62 |
| 整条腿净位移 | 3.42 | 2.53 | 2.72 | 2.60 | 2.82 |

`2.69` 落在两种估计的区间内，`2.47` 则在区间之外。修正测量源与观测量程之后，两个增益的仿真指标几乎完全相同（平均马氏距离 `0.0531` 对 `0.0532`），说明此前的差距完全来自截断，而非模型精度。保持与 Lab 1 一致还有一个好处：已提交的 `33377006_m1_2.py` 与本滤波器描述的是同一台机器人。

位置更新使用中间速度和中间航向：

```text
x_next = x + speed_mid * sin(heading_mid) * dt
y_next = y + speed_mid * cos(heading_mid) * dt
```

机器人同时转向和加速时，这种积分方式比只使用旧状态或新状态更加准确。

## 5. EKF 预测步骤

非线性状态预测为：

```text
x_k^- = f(x_(k-1), u_k)
```

协方差预测为：

```text
P_k^- = F_k P_(k-1) F_k^T + Q
```

`F_k` 是运动模型的雅可比矩阵。由于模型包含限幅、死区、变化率限制和角度归一化，[`EKF.py`](./EKF.py) 使用中心数值差分计算雅可比，而不是使用容易出错的全局符号公式。

对于第 `i` 个状态分量：

```text
F[:, i] = (f(x + epsilon_i, u) - f(x - epsilon_i, u)) / (2 * epsilon)
```

内部动力学计算使用 `float64`，避免很小的雅可比差值被 `float32` 舍入误差吞掉。

## 6. 测量模型与 EKF 更新

测量模型是线性的：

```text
h(x) = [航向角, 速度]
```

对应矩阵为：

```python
H = [[0, 0, 1, 0],
     [0, 0, 0, 1]]
```

更新公式为：

```text
新息：               nu = z - h(x^-)
新息协方差：          S = H P^- H^T + R
卡尔曼增益：          K = P^- H^T S^-1
后验状态：            x = x^- + K nu
```

航向新息会被归一化到 `[-pi, pi)`。这可以避免把刚小于 `-pi` 的测量与刚小于 `+pi` 的预测误判成接近 `2*pi` 的巨大误差。

程序通过求解线性方程计算卡尔曼增益，而不是显式计算 `S^-1`，数值稳定性更好。

### 6.1 测量量的来源（真机与仿真不同）

`lab2.py` 中的 `extract_measurement()` 决定 `z` 从哪里来，这一点在真机上尤其关键。

**仿真**：观测值是真值加高斯噪声，本身就是合法的测量量，直接使用 `obs[2:4]`。

**真机**：速度改用 `info["velocity"]`（电机编码器），不再使用观测里的速度。原因是 `sphero_unsw` 的两个接口都只是指令回显：

```python
def get_speed(self):    # 文档："current target speed"
    return self.__speed         # 上一次 set_speed() 写入的值
def get_heading(self):  # 文档："target directional angle"
    return self.__heading       # 上一次 set_heading() 写入的值
```

2026-08-14 的 200 步真机日志直接证实了这一点：`speed` 列与 `speed_cmd` 列在全部 200 行上逐位相同，且只取 `0.10` 这一个值；`heading` 列与 `heading_cmd` 列最大只差 `1.745e-02 rad`，恰好等于 `int(degrees(...))` 取整造成的 1°。

把指令回填当作测量量，等于让滤波器拿自己的输入去校正自己。当时模型预测的稳态速度是 `0.182 m/s`，而"测量"恒为 `0.10 m/s`，于是速度新息固定停在 `-0.082 m/s`，相当于假定测量标准差 `0.025` 的三倍多——这是一个恒定偏置，而非 EKF 假设的零均值白噪声。

编码器速度只取模长 `hypot(vx, vy)`：接口文档说明 `x`/`y` 分别是右向和前向，但没有说明该坐标系是机体系还是世界系，而模长在两种约定下相同；正负号则取自速度指令，不存在歧义。若蓝牙丢帧导致该字段缺失，函数回退到观测值，避免把 `NaN` 送进滤波器。

**航向改用 IMU 的 yaw**，由 `ImuHeadingSensor` 提供。`get_orientation()` 的文档写明 yaw 由陀螺仪测量，而 instructions.md 明确把陀螺仪列为真机可用的测量源，因此这正是作业期望的做法。

采用它需要解决两个未知量，其中只有一个需要假设：

- **零点被精确消除，无需任何假设。** 滤波器不使用 yaw 的绝对值，而是把第一帧读数记作参考，之后只使用相对该参考的差值。这样 IMU 自身原点落在哪里完全不影响结果。
- **符号必须假设。** `set_heading()` 与 IMU yaw 在文档中都被描述为「自上而下看顺时针为正」，因此 `IMU_YAW_SIGN = +1` 是合理默认，但这台机器人上从未实测。

关键在于猜错的后果是**可检测且可恢复**的。符号反了会使测得航向与指令航向相差约 180°，并持续整条腿（50 步）；而真实的转向瞬态最多偏离 90°（脚本每次航向跳变都是 90°），并在转向限速 `2.61 rad/s` 下 6 步内收敛。两者之间有清晰的间隔，因此 `ImuHeadingSensor` 以 120° 为阈值、连续 10 步为耐受度：一旦持续超限，它会打印警告、停用 IMU 并回退到观测值。这样即使符号猜错，代价也只是一条警告，而不是整次实验作废。

诊断日志同时记录原始 `imu_yaw_deg` 与实际送入滤波器的 `z_heading`，跑完对照 `heading_cmd` 即可确认符号是否正确。

## 7. 协方差更新与数值稳定性

后验协方差使用 Joseph 形式：

```text
P = (I - KH) P^- (I - KH)^T + K R K^T
```

与简化形式 `(I-KH)P` 相比，Joseph 形式在浮点运算中更容易保持矩阵对称和半正定。

每次预测和更新后，程序都会重新对称化协方差，并把数值舍入导致的极小负特征值提升到一个很小的正数。CSV 分析器还会独立检查位置协方差，任何非正定结果都会被拒绝。

## 8. 噪声矩阵

仿真过程噪声为：

```python
Q = diag([3.125e-6, 3.125e-6, 1.0e-4, 2.5e-5])
```

实机实验使用更大的位置过程噪声：

```python
Q_real = diag([3.125e-5, 3.125e-5, 1.0e-4, 2.5e-5])
```

它用于表示未建模的实机运动、地面差异和 sim-to-real 残差，避免真实机器人滤波器对自己的位置精度过度自信。

测量噪声为：

```python
R = diag([0.025^2, 0.025^2])
```

初始协方差为：

```python
P0 = diag([1e-6, 1e-6, 6.25e-4, 6.25e-4])
```

仿真器和机器人都从已知原点重置，所以初始位置不确定性很小；初始航向和速度的不确定性更大。

## 9. 200 步正方形轨迹

默认轨迹分成四段：

| 步数 | 相对初始航向 | 运动方向 |
| ---: | ---: | --- |
| `1-50` | `0` | 沿初始 `+y` 方向直行 |
| `51-100` | `pi/2` | 正方形右侧 |
| `101-150` | `pi` | 正方形后侧 |
| `151-200` | `-pi/2` | 左侧返回起点附近 |

每一段都使用：

```python
action = np.array([0.10, heading], dtype=np.float32)
```

运动开始前，仿真器航向会与机器人重置后的航向对齐。程序没有额外的校准运动，也不会朝 `(0.5, 0.5)` 目标点移动。

## 10. 每一步的预测与更新顺序

每个控制周期执行：

1. 选择默认轨迹动作或键盘控制动作；
2. 推进仿真器；
3. 连接实机时推进机器人；
4. 调用 `ekf.predict(action)`；
5. 调用 `ekf.update(measurement)`；
6. 把后验状态和协方差发送到可视化窗口；
7. 保存一行 CSV 数据；
8. 等待下一个绝对 `0.1 s` 时刻。

时间同步代码为：

```python
next_tick += DT
time.sleep(max(0.0, next_tick - time.monotonic()))
```

使用单调时钟和绝对目标时刻，可以减少反复 `sleep(0.1)` 造成的累计时间漂移。

## 11. 可视化窗口中的线条

动画中的颜色含义为：

- 绿色：仿真器 ground truth；
- 蓝色：带噪声的仿真里程计；
- 紫红色：EKF 后验估计。

评分时主要比较绿色与紫红色轨迹。机器人附近的圆或椭圆来自 EKF 位置协方差。黄色点只是环境的目标标记，不负责控制默认的正方形轨迹。

## 12. CSV 输出

自动评分文件名为：

```text
<student-id>_lab2.csv
```

文件必须包含正好 200 行和七列：

```text
sim_x,sim_y,real_x,real_y,P_xx,P_xy,P_yy
```

这里的 `real_x` 和 `real_y` 表示 EKF 的平均位置估计，而不是原始位置里程计。`P_xx`、`P_xy` 和 `P_yy` 可以还原对称的后验位置协方差：

```text
P_position = [[P_xx, P_xy],
              [P_xy, P_yy]]
```

写入前，程序会验证行数、数组形状和所有数值是否有限，然后以原子替换方式生成最终 CSV。

## 13. 自动评分指标

每一步的位置误差为：

```text
e_k = 仿真位置_k - EKF位置_k
```

平方 Mahalanobis 距离为：

```text
d_k^2 = e_k^T P_position_k^-1 e_k
```

两项评分要求为：

| 指标 | 通过阈值 |
| --- | ---: |
| 平均平方 Mahalanobis 距离 | `<= 4.0` |
| 位于 2 自由度 95% 卡方门限内的比例 | `>= 0.90` |

统计量过高表示滤波器过度自信，即实际误差大于协方差所预测的范围；统计量长期过低则可能表示滤波器过于保守。

## 15. 停车、蓝牙与日志

真实机器人环境由上下文管理器和 `finally` 保护。第 200 步完成后，程序依次：

```text
调用 emergency_stop
  -> 停止诊断日志
  -> 关闭 Robot 对象
  -> 退出 SpheroEduAPI
  -> 释放蓝牙连接
  -> 根据需要仅保留仿真窗口
```

因此，使用 `--hold` 时，真实机器人并不会继续保持蓝牙连接。关闭窗口或按 `Q` 只是用于退出最终仿真画面。

日志共有两份：

```text
logs/lab2_robot.csv         由框架 Visualiser 写出，记录轨迹与指令
logs/lab2_diagnostics.csv   由 DiagnosticLog 写出，记录原始传感器与滤波器内部量
```

诊断日志每步记录 26 列，包括高精度时间戳、速度与航向指令、观测值、编码器 `vx/vy`、IMU `yaw`、陀螺仪 `z`、**实际送入滤波器的测量 `z_heading` / `z_speed`**、里程计位置、EKF 状态、两路新息、NIS 以及位置协方差。它存在的目的是让**一次**真机运行就能回答那些只有在机器人面前才能确定的问题：`get_velocity()` 使用的坐标系、`IMU_YAW_SIGN` 是否为 `+1`、以及编码器测量的真实噪声（用于标定 `R`）。记录 `z_*` 而不是事后推算，可以直接看出每一步用的是传感器还是回退值。即使实验中途被 `Q` 中断，该日志仍会写出——需要中断的那一次运行，恰恰是最值得分析的。

时间戳使用 `time.perf_counter()` 而非 `time.monotonic()`。在本机上 `monotonic` 与 `time` 都由 `GetTickCount64()` 实现，分辨率为 `15.625 ms`，占 `100 ms` 控制周期的 16%，既无法测量抖动，用它控制节拍本身也会引入同等量级的误差；`perf_counter` 由 `QueryPerformanceCounter()` 实现，分辨率 `0.1 us`。改用后实测步长为 `100.00 ms`，标准差 `0.23 ms`。

日志、自动评分 CSV、分析 PNG 和缓存都已被 Git 忽略（`logs/.gitignore` 的规则是 `*`）。
